# Media audit — October 8, 2026

## Findings and changes

- Board and staff avatars only requested `sizes.thumbnail.url`. Missing sizes or failed requests immediately showed a generic icon. They now try the original image after a thumbnail fails, use `object-fit: cover`, and preserve the focal point for that fallback.
- Thumbnail URLs had no version parameter. Cropping or changing a focal point overwrites the same object, so browsers could reuse an older response. CMS images now include the media document's `updatedAt` in their URL. URL construction preserves existing queries and fragments.
- Media edits and deletions had no frontend revalidation hooks. Media now invalidates the frontend layout and media-dependent document/global caches. Team publishing/deletion also invalidates pages containing team blocks. Global cache keys now include relationship depth so an earlier shallow query cannot determine later populated results.
- Custom derivative filenames omitted extensions. Newly generated thumbnail/meta files now have their actual extension. Existing database records still load their saved URLs, including legacy extensionless objects.
- Payload can omit image sizes when both source dimensions are smaller than the target. Thumbnails now explicitly permit enlargement to generate a 300 × 300 square even for small uploads. Originals and metadata images avoid enlargement.
- Several frontend components bypassed the shared media URL helper and ignored focal coordinates. Hero, carousels, link cards, and the shared image component now use versioned URLs and focal positioning. Broken/empty carousel URLs are skipped. Responsive `sizes` use valid CSS lengths; unnecessary quality 100 and the large generic blur placeholder were removed.
- Placeholder generation could reject an otherwise valid image upload. It now logs a warning and allows the upload without a placeholder when generation fails. New placeholders use 8 pixels rather than 32 to reduce embedded image data.
- R2 URL construction interpolated unencoded filenames and could insert an `undefined` prefix. It now encodes path segments and supports absent prefixes. SEO images prefer the metadata derivative and correctly handle absolute and relative URLs.
- Local Payload file URLs remain relative, including absolute localhost/file-endpoint URLs, so Next does not attempt a remote image fetch against a loopback/private host.

## Mark's image

The public team API returns a populated media relationship with a thumbnail URL. On inspection the CDN returned HTTP 200, `Content-Type: image/webp`, and 9,012 bytes for that URL. That confirms the stored thumbnail exists now; it does not establish the cause of every intermittent browser failure. Request failures, stale page data, and reused URLs were previously unhandled. The changes address those failure paths, but a browser/network reproduction is still needed to attribute the reported intermittent failure conclusively.

The stored source is 1600 × 1600, thumbnail 300 × 300, and focal point `(57, 32)`. For an already square image, a square derivative can retain the entire image; a focal point does not imply zooming toward the face.

## Crop workflow

Payload applies the selected crop before generating image sizes. The focal point guides any further crop required to fit a derivative's aspect ratio. For a tightly framed portrait, select a square crop around the head and shoulders, apply it, save the media document, and inspect **Preview Sizes → thumbnail**. Moving the focal point alone on a square source will not tighten a square thumbnail.

Editing a crop changes the stored source; retain a separate full-resolution master if it may be needed later. Existing images are not automatically regenerated by changing the upload configuration. To apply the new filename/resize rules to a particular image, re-upload its source through Media and save it after deployment. No production records or R2 objects were modified during this audit.

The regression tests exercise Payload's actual crop/resize implementation with synthetic images, including a selected crop with a focal point at its edge. This verifies server-side output stays within that crop for the tested case; it does not test every admin UI gesture or image format.
